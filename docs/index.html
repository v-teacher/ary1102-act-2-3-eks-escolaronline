05 · PERSISTENCIA ADMINISTRADA

La base de datos

  1. Configurar RDSMySQL, cifrado y acceso privado

La inicialización creó la tabla y cinco productos. La prueba posterior conservó un registro al eliminar y reemplazar un pod de consultas.

Esa prueba demuestra persistencia fuera del pod. No demuestra un failover de RDS ni acredita un RPO o un RTO.

Nota para explicar Multi-AZ

El despliegue Multi-AZ de instancia mantiene un standby para disponibilidad. No equivale a una réplica de lectura. Consultar la documentación vigente de RDS.

09 · OPERACIÓN Y CIERRE

Una implementación incluye
diagnóstico y retiro de recursos

Diagnóstico por capas

Imagen, pod, Service, DNS, Ingress y base de datos.

kubectl get pods,svc,ingress
kubectl logs deployment/frontend
kubectl get hpa
kubectl top pods

Retiro controlado

Eliminar el Ingress y esperar el retiro del ALB. Después revisar el plan de destrucción de Terraform.

EKS, nodos, NAT y RDS generan costos mientras permanezcan desplegados. Destruir esta prueba elimina sus datos e imágenes.
