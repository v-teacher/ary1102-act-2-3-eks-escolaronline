La inicialización creó la tabla y cinco productos. La prueba posterior conservó un registro al eliminar y reemplazar un pod de consultas.

Esa prueba demuestra persistencia fuera del pod. No demuestra un failover de RDS ni acredita un RPO o un RTO.

Nota para explicar Multi-AZ

El despliegue Multi-AZ de instancia mantiene un standby para disponibilidad. No equivale a una réplica de lectura. Consultar la documentación vigente de RDS.

VPC, DNS y seis subredes

ACT_VPC=$(aws ec2 create-vpc --cidr-block 10.24.0.0/22 \

  --tags Key=kubernetes.io/role/elb,Value=1

AWS CLI · PASO 3

Salida pública y salida privada

ACT_IGW=$(aws ec2 create-internet-gateway \
  --query InternetGateway.InternetGatewayId --output text)
aws ec2 attach-internet-gateway --vpc-id "$ACT_VPC" \
  --internet-gateway-id "$ACT_IGW"
ACT_PUBLIC_RT=$(aws ec2 create-route-table --vpc-id "$ACT_VPC" \
  --query RouteTable.RouteTableId --output text)
aws ec2 create-route --route-table-id "$ACT_PUBLIC_RT" \
  --destination-cidr-block 0.0.0.0/0 --gateway-id "$ACT_IGW"
ACT_EIP=$(aws ec2 allocate-address --domain vpc \
  --query AllocationId --output text)
ACT_NAT=$(aws ec2 create-nat-gateway --subnet-id "${ACT_PUB[0]}" \
  --allocation-id "$ACT_EIP" --query NatGateway.NatGatewayId --output text)
aws ec2 wait nat-gateway-available --nat-gateway-ids "$ACT_NAT"
ACT_APP_RT=$(aws ec2 create-route-table --vpc-id "$ACT_VPC" \
  --query RouteTable.RouteTableId --output text)
aws ec2 create-route --route-table-id "$ACT_APP_RT" \
  --destination-cidr-block 0.0.0.0/0 --nat-gateway-id "$ACT_NAT"

Crear y asociar tablas: públicas con ruta al IGW, aplicación con ruta al NAT, datos sin ruta a Internet. Activar IP pública solo en las subredes públicas.

Las llamadas create-route-table, create-route y associate-route-table se detallan en la guía completa.

AWS CLI · PASO 4

Clúster y nodos privados

ACT_CLUSTER_ROLE=$(aws iam list-roles --query "Roles[?contains(RoleName,'LabEksClusterRole')].Arn | [0]" --output text)
ACT_NODE_ROLE=$(aws iam list-roles --query "Roles[?contains(RoleName,'LabEksNodeRole')].Arn | [0]" --output text)
ACT_EKS_VPC_CONFIG="subnetIds=${ACT_APP[0]},${ACT_APP[1]},endpointPrivateAccess=true,"
ACT_EKS_VPC_CONFIG+="endpointPublicAccess=true,publicAccessCidrs=$ACT_OPERATOR_CIDR"
aws eks create-cluster --name "$ACT_NAME" \
  --kubernetes-version 1.34 --role-arn "$ACT_CLUSTER_ROLE" \
  --resources-vpc-config "$ACT_EKS_VPC_CONFIG"
aws eks wait cluster-active --name "$ACT_NAME"
aws eks create-nodegroup --cluster-name "$ACT_NAME" \
  --nodegroup-name "$ACT_NAME" --node-role "$ACT_NODE_ROLE" \
  --subnets "${ACT_APP[@]}" --instance-types t3.medium \
  --scaling-config minSize=2,maxSize=4,desiredSize=2

El API público queda limitado a la IP del operador (/32). Los nodos usan subredes privadas, AL2023 x86_64 y roles existentes. Esperar ACTIVE y nodos Ready.

AWS CLI · PASO 5

RDS y acceso MySQL

ACT_EKS_SG=$(aws eks describe-cluster --name "$ACT_NAME" \
  --query cluster.resourcesVpcConfig.clusterSecurityGroupId --output text)
ACT_DB_SG=$(aws ec2 create-security-group \
  --group-name "$ACT_NAME-db" --vpc-id "$ACT_VPC" \
  --query GroupId --output text)
aws ec2 authorize-security-group-ingress \
  --group-id "$ACT_DB_SG" --protocol tcp --port 3306 \
  --source-group "$ACT_EKS_SG"
aws rds create-db-subnet-group --db-subnet-group-name "$ACT_NAME" \

node scripts/cli-rds-input.mjs

El JSON privado define MySQL, db.t3.micro, Multi-AZ, cifrado, contraseña y acceso no público. El helper lo genera sin imprimir la contraseña; la regla 3306 acepta solo el grupo EKS.
